[Shixi Lin](https://shixilin.com/) が制作しました。

Prism Desk は、サブスクリプション型 CLI 向けの Windows ワークスペースです。あるアカウントの利用枠を使い切ったら、会話や進捗メモを手作業で再構成することなく、別のアカウントにタスクを引き継げます。プロジェクトフォルダーは変わりません。

Prism が作業時間の節約に役立ったら、[今後の開発をご支援いただけるとうれしいです](https://shixilin.com/support?lang=ja)。

### バージョンとダウンロード

**[最新リリース](https://github.com/shixi-11/prism-desk/releases/latest)** · **[インストールガイド](#install)**

Prism は現在、**Windows でのソースからのインストール**に対応しています。単体の `.exe` または `.msi` インストーラーは公開していません。GitHub の「Source code」ダウンロードにはソースファイルが含まれています。インストールガイドに従って、デスクトップアプリをビルドして起動してください。各安定版リリースには、バージョンタグが一つと、英語および簡体字中国語の完全な変更履歴を掲載したページが一つあります。

### できること

| 機能 | 実際の使い方 |
| --- | --- |
| 同じタスクを続ける | 別のアカウントに作業を引き継ぐ際、最初の依頼、会話、進捗メモ、記録済みのツール結果をまとめて保持します。 |
| 実行アカウントを選ぶ | 設定済みの Codex、Claude、Grok CLI プロファイルを選択します。それぞれ独立したログインディレクトリを使用します。使わないアカウントはアカウントパネルから削除できます。タスク履歴とローカルのログインフォルダーは保持されます。 |
| モデルと推論設定を変更する | タスクの途中でどちらの設定も調整できます。変更は次の実行に適用され、そのタスク内でアカウントごとに保存されます。 |
| Codex Fast モード | 対応モデルの応答を高速化し、クレジット消費が増加します。初期設定はオフ。タスク内のアカウントごとに保存され、推論レベルを変えずに次の実行から適用されます。 |
| 利用枠を確認する | プロバイダーから報告された割合、利用枠の期間、リセット時刻を、取得できる範囲で表示します。Codex のリセットクレジットでは、取得できた場合に各クレジットの有効期限も表示します。 |
| 利用枠を使い切ったら引き継ぐ | 自動引き継ぎを有効にするか、次のアカウントを自分で選択します。Prism は前の実行が終了するのを待ってから続行します。 |
| ローカルのスキルやツールを使う | アシスタントへの指示、スキルフォルダー、インストール済みアプリケーションを Prism に指定します。検出されたエントリーポイントと、対応するアプリケーション操作を確認できます。 |
| 作業をローカルに保存する | タスクを永続的に保存するフォルダーを選び、進捗メモを追加し、会話記録を Markdown 形式でエクスポートできます。 |
| 自分の言語で作業する | 右から左に表示するアラビア語を含む九つのインターフェース言語から選択でき、明るい砂漠テーマと暗い砂漠テーマを切り替えられます。 |

### インストール

以下のコマンドで安定版 **v0.1.21** をインストールします。[最新リリース](https://github.com/shixi-11/prism-desk/releases/latest)で、バージョンと二言語の変更履歴を確認してください。

Windows、Git、Node.js 22.12 以降、npm、および利用するプロバイダーの公式 CLI が必要です。各 CLI に個別にサインインしてください。

```powershell
git clone --branch v0.1.21 https://github.com/shixi-11/prism-desk.git
cd prism-desk
npm install
npm run build
npm run build:desktop
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-host.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1
```

ビルドスクリプトは、CLI の子プロセスをまとめて停止するための Windows プロセスホストをコンパイルします。Windows に付属する .NET Framework コンパイラーを使用します。

### 最初のタスクを始める前に

利用する各プロバイダーの公式 CLI をインストールし、その CLI からサインインしてください。ウェブサイトやデスクトップアプリへのサインインだけでは、Prism の設定は完了しません。

- **Codex:** [CLI インストールガイド](https://developers.openai.com/codex/cli/)に従い、ChatGPT アカウントでサインインしてください。
- **Claude:** [Claude Code](https://code.claude.com/docs/en/setup) をインストールし、対応する Claude サブスクリプションで[サインイン](https://code.claude.com/docs/en/authentication)してください。Prism は実行前にサブスクリプションのログイン状態と追加使用量の設定を確認します。追加使用量は無効にする必要があります。
- **Grok:** 公式 Grok CLI をインストールし、サブスクリプションのアカウントでサインインしてください。

**アカウント → アカウントを接続**を開き、Codex、Claude、Grok のいずれかを選択して、アカウントに名前を付けます。**保存して続ける → ログインリンクを取得 → ログインリンクをコピー**で、公式 CLI の認可フローを開始します。リンクをブラウザーのアドレスバーに貼り付けてください。Claude に認可コードが表示された場合は、コード全体を**認証コード**に貼り付け、**認証コードを送信**を選択してください。コードは待機中の公式 CLI にのみ送信され、その後入力欄から消去されます。認可後、Prism はサブスクリプションのログインを検証し、再起動せずにアカウントを利用可能にします。このページでは、既存のログインの確認、認可のキャンセル、リンクの再コピー、プロファイルの名前変更、アカウントの無効化と有効化も行えます。無効化しても過去のタスクと認証情報は保持されます。詳細設定では、公式 CLI の実行ファイルを選択したり、既存の独立したログインディレクトリをインポートしたりできます。確立済みのアカウントディレクトリとプラットフォームの識別情報は変更できません。CLI が見つからない場合は、公式のインストール手順へのリンクが表示されます。今後追加するプラットフォームには、それぞれ専用のプロバイダーアダプターと実行アダプターが必要です。

### 一般的なタスクの流れ

1. **新規 → 新しい会話**をクリックして名前を入力します。作業フォルダーを空欄にすると専用の永続的なワークスペースを使い、保存済みプロジェクトも選択できます。**新規 → 新しいプロジェクト**ではフォルダーを作成するか、既存のフォルダーをファイルを移動せずに保存できます。空のプロジェクトもサイドバーに残ります。プロジェクト横の **＋** で、そのフォルダーに新しい会話を作成できます。複数の会話で同じプロジェクトを利用できます。
2. 実行アカウント、モデル、推論の強度を選択します。レビューには**読み取り専用**、編集には**プロジェクト内を編集**を使用します。
3. 依頼を入力し、**Ctrl + Enter** で送信します。作業の進行に合わせて、会話と実行ログを確認できます。
4. 重要な決定や残りの作業を進捗メモに追加します。アカウントを変更するには、次のアカウントを選んで引き継ぎ操作を行います。必要な場合は、先に現在の実行を停止してください。
5. タスクの鉛筆ボタン、ダブルクリック、または **F2** で名前を変更できます。**Enter** で保存、**Esc** でキャンセルします。
6. 同じタスクで作業を続けます。Markdown のコピーが必要になったら記録をエクスポートするか、タスク保存フォルダーを開いてローカルファイルを確認してください。

次のアカウントには、保存済みの会話、進捗メモ、ツール記録が渡されます。プロバイダー内部のモデル状態は転送されません。

### メッセージ、設定、プレビュー

#### 目標と計画

入力欄の上にあるコンパクトな**目標バー**には、保存済みの目標、実行状態、累積実行時間が表示されます。バーから目標の編集、一時停止、再開、削除ができ、展開すると目標の全文、編集可能な計画、実行の詳細を確認できます。一時停止すると現在の実行が停止し、キュー内のメッセージは保留されます。削除では実行の停止を待ってから目標を削除し、未処理のメッセージを確認用に保留します。会話記録とワークスペースのファイルは引き続き利用できます。タイマーには、一時停止中、待機中、アプリを閉じている間の時間は含まれません。公式の利用枠の枯渇は、ネットワーク障害やログイン失敗とは別に表示されます。

Codex に目標の設定や変更を依頼すると、Prism のネイティブツールを通じて目標を保存できます。ほかのエントリーでは、インターフェース上で採用できる目標を提案できます。チャットの文章に目標を保存したと書かれていても、それだけで実際の目標が変更されることはありません。**先に計画を立てる**は読み取り専用権限で実行し、確認用の草案を返します。メッセージが未確定の計画についての議論にのみ使われる場合、入力欄にその旨が明示されます。**計画を確定して実行**を選ぶと、タスクに設定された権限で実装を開始します。目標と計画はセッションをまたいで保持され、引き継ぎ記録にも残ります。

#### モデルと引き継ぎ

**切り替えて続ける**を使うと、同じアカウント内でモデルの変更を適用できます。確定した実行には、アカウント、モデル、推論レベルが記録されます。選択内容を保存しただけでは、切り替え完了とは表示されません。**自動引き継ぎの設定**を開くと、ドラッグで並べ替えられるアカウント一覧が表示され、各アカウントのモデルと推論レベルを設定できます。変更は現在のタスクに自動保存されます。一覧では、タスクが必要とする書き込み権限を満たせないアカウントが示されます。引き継ぎでは画像対応も考慮されます。

#### アカウントとウィンドウ

各アカウントカードには、鉛筆ボタンで編集できる**表示名**があります。変更されるのは表示名であり、ログイン時の識別情報は変わりません。Codex のネイティブな質問と、対応している質問・選択肢リスト形式のメッセージでは、クリックできる選択肢と自由入力の回答を利用できます。Windows のタイトルバーの **×** を押すと、Prism は通知領域に隠れます。進行中の作業を停止して終了するには、トレイメニューの **Prism を終了**を使用してください。

#### タスクの整理

タスクを右クリックすると、名前の変更、ピン留め、未読にする、アーカイブ、プロジェクトやセクション別のグループ化、共有、コピー、分岐の作成、フォルダーや会話を開く、別のウィンドウを開く、削除を行えます。サイドバーの**アーカイブと削除済み**から、非表示のタスクを復元できます。タスクを削除しても、ワークスペースと会話ファイルは保持されます。プロジェクトの選択を変更すると、その後の作業の実行場所が変わります。既存のファイルは元のフォルダーに残ります。分岐を作成すると新しい CLI セッションが始まり、会話の添付ファイルがコピーされます。独立したワークスペースのオプションでは、空のフォルダーから始まります。共有では、コピーまたは保存できるローカルの Markdown 文書をプレビューします。ホスティングされた公開リンクは作成しません。タスクの変更は、開いているウィンドウ間で同期されます。

実行中でない会話を別のプロジェクト名にドラッグすると、履歴と下書きを保ったまま作業フォルダーを変更できます。既存ファイルは元の場所に残ります。ファイル権限の横にある**関連プロジェクト**で追加したフォルダーには、次回の実行から現在の権限が適用されます。制限付きの複数フォルダーへのアクセスは Codex と Claude に対応し、他のプロバイダーにはフルアクセスが必要です。他の会話は統合されません。

**Fast** スイッチは送信ボタンの横にあります。Prism のロゴをクリックすると、下書きや実行中の作業を保ったまま、会話が選択されていないホームに戻ります。Claude の進捗メッセージはまとめて表示され、正常終了時の最終回答は個別に残ります。バックグラウンドのプロセスホストはコンソールウィンドウを作成せず、同時に行われるモデル一覧の要求は一度の CLI 問い合わせを共有します。

#### 表示と利用枠

上部バーには、下部の実行ログおよびアカウントサイドバーの表示切り替えがあります。これらの状態はローカルに保存されます。「アカウント」の**全アカウントを確認**は、設定済みの全プロファイルに問い合わせ、利用可能な枠、リセット時刻、Codex のリセットクレジット、クレジットの有効期限を表示します。一つの問い合わせが失敗しても、残りのアカウントの確認は続行します。

#### 画像

スクリーンショットの貼り付け、入力欄への画像のドロップ、または画像ボタンで画像を追加できます（最大五枚、各 10 MB）。Codex にはローカル画像が渡され、Claude にはサブスクリプションの確認に合格した場合にネイティブの画像コンテンツが渡されます。Claude の画像を使った実行は、サインイン済みアカウントではまだ検証していません。Grok は、CLI が直接の画像入力への対応を示す場合は画像コンテンツを直接使用し、それ以外はネイティブの Read ツールで添付画像を開きます。この経路は、サブスクリプションにサインインした状態で検証済みです。

#### メッセージと下書き

作業の実行中にも追加のメッセージを送信できます。メッセージは順番に待機し、キャンセルもできます。設定では、Enter または Ctrl/⌘+Enter による送信と、キューへの追加またはリアルタイムの指示を選択できます。リアルタイムの指示は Codex の進行中のターンを使用し、ほかのプロバイダーではキューに追加されます。送信が失敗または中断した場合、後続のメッセージは確認用に保留されます。アプリを開いたままタスクを切り替えても、下書きは保持されます。

#### ファイルのプレビュー

プレビューパネルを開くか、ファイルリンクをクリックすると、画像、PDF、Markdown、コード、テキストを表示できます。テキストファイルは編集して保存でき、保存前に外部での変更を確認します。HTML プレビューでは単独のページを表示できます。対話型プロジェクトでは、実行中の HTTP アドレスを使用できます。一部のウェブサイトは埋め込み表示をブロックします。アクティビティパネルには、CLI から提供される推論の要約、計画、実行状態が、取得できる場合に表示されます。

### 自動更新

1. **更新を確認**は「更新があります」または「最新バージョンです」と表示します。ダウンロードや再起動は行いません。
2. **ダウンロードして準備**は、準備が完了すると「更新の準備ができました」と表示します。現在のバージョンを引き続き使用できます。
3. **更新して再起動**は、クリックした後にのみ再起動します。新しいバージョンの起動に成功すると、「vX.X.X に更新しました」が一度だけ表示されます。通常の起動やロールバックでは、この成功メッセージは表示されません。

サイドバーの**更新を確認**は、公開済みの安定版 [GitHub Releases](https://github.com/shixi-11/prism-desk/releases) を参照します。ダウンロード前に、インストール済みのバージョン、利用可能なバージョン、変更履歴を表示します。**後で**を選ぶと、現在のバージョンを引き続き使用できます。main ブランチへの通常のコミットでは、更新通知は表示されません。自動確認は初期状態で有効です。Prism は起動後と四時間ごとに確認します。「更新を確認」の横に点灯する青い点と、上部バーの更新アイコンは、利用可能なバージョンがあることを示します。確認だけでは、アプリのダウンロード、インストール、再起動は行いません。都合のよいときに**ダウンロードして準備**を選び、その後に**更新して再起動**を選択してください。青い点は、インストール済みのリビジョンが最新になるまで表示されます。再起動前に各ウィンドウの下書きが保存されます。タスク、キュー内のメッセージ、アカウント操作、編集ダイアログ、プレビューがある間は、それらが完了または閉じられるまで再起動できません。

更新後も、同じアカウント設定、タスク保存先、ユーザーデータディレクトリを使用します。元のチェックアウトと以前のインストールは引き続き利用できます。ダウンロードやビルドに失敗しても、実行中のバージョンは影響を受けません。新しいアプリが起動を完了できなかった場合は、Prism をもう一度開くと以前のバージョンに復元されます。ローカルのソースに変更がある場合は更新できず、更新の準備には 2 GB 以上の空き容量が必要です。Git はインストールしたままにする必要があります。デスクトップビルドには、今後のビルドに必要な Node ランタイムと npm が含まれています。このアップデーターの導入前にインストールした環境では、上記のインストールコマンドを使い、一度手動でプルして再ビルドする必要があります。

### 設定

ほとんどの場合、**アカウント → アカウントを接続**からアカウントを接続できます。以下の設定ファイルは、上級者向けの代替手段です。例をコピーする前に、既存のファイルをバックアップしてください。

```powershell
New-Item -ItemType Directory -Force .local
Copy-Item config.example.json .local/config.json
```

自分のコンピューターに合わせて `.local/config.json` を編集してください。`PRISM_CONFIG` に設定ファイルの絶対パスを指定することもできます。

単一アカウントの設定は次のようになります。例のログインディレクトリを自分のものに置き換え、アカウントで利用可能なモデルを選んでください。`profiles` に項目を追加すると、実行アカウントが増えます。

```json
{
  "profiles": [
    {
      "id": "codex-personal-1",
      "provider": "Codex",
      "name": "Personal 1",
      "home": "C:/PrismAccounts/codex-personal-1",
      "executable": "codex.exe",
      "model": "gpt-5.6-sol",
      "write": true
    }
  ]
}
```

| フィールド | 用途 |
| --- | --- |
| `profiles` | 実行アカウント：ID、プロバイダー、表示名、ログインディレクトリ、実行ファイル、モデル、書き込み権限 |
| `storageRoot` | タスク記録の永続的な保存先 |
| `assistant.path` | `SKILL.md` を含むアシスタントディレクトリ（任意） |
| `assistant.instructions` | タスク間で共有する指示（任意） |
| `skillsPath` | 共有スキルディレクトリ |
| `apps` | アプリケーション名と、実行ファイルまたはエントリーファイルのパスとの対応付け |

ローカルリソースには絶対パスを使用し、アカウントごとに独立したログインディレクトリを用意してください。プロファイル ID は変更しないでください。既存のタスクは、この ID でアカウントを識別します。既定のプロファイル構造は [electron/config.cjs](electron/config.cjs) で定義されています。

`storageRoot` を設定しない限り、タスクはアプリケーションのユーザーデータディレクトリに保存されます。ログイン認証情報は、プロバイダー自身のディレクトリに保持されます。ローカル設定、タスク記録、ログは Git の対象から除外されています。

### ファイルとコマンドの権限

入力欄で**読み取り専用**、**プロジェクト内を編集**、**フルアクセス**を選択します。フルアクセスは Codex、Claude、Grok で利用できます。OS の権限の範囲内で、プロジェクト外のファイルへのアクセスを許可し、ツールの実行を自動承認します。実行中に行った変更は、次の実行に適用されるよう保留されます。新規インストールでは、対応するアカウントの既定値は「プロジェクトを編集」です。**新しいタスクの既定の権限にする**を選ぶと設定を保存できます。既存のタスクは、それぞれの権限を保持します。読み取り専用のアダプターは、引き続き読み取り専用です。

### アカウントとローカルツール

Codex、Claude、Grok のアダプターは、ファイルを編集するタスクに対応しています。Grok は選択したタスク権限に従います。読み取り専用では編集ツールとシェルツールを無効にし、「プロジェクトを編集」では CLI のワークスペースプロファイルと操作確認を使用し、「フルアクセス」ではツールの実行を許可します。`write: false` が設定された既存のプロファイルは、明示的に有効化するまで読み取り専用のままです。利用できるモデルは、インストール済みの CLI と選択したアカウントによって異なります。

利用枠パネルには、プロバイダーから返された情報が表示されます。有効な Grok の統合利用枠期間では、使用量ゼロの省略は公式クライアントの解釈に従います。空、不正な形式、期限切れの応答は、不明のまま扱います。Claude への問い合わせは、一時的な接続障害や使用量の応答がない場合に一度だけ再試行しますが、認証失敗後は再試行しません。認証エラーやネットワークエラーを利用枠の枯渇とみなして、アカウントを切り替えることはありません。自動引き継ぎには、認識可能な利用枠枯渇の応答と、前の実行の完了が必要です。

アカウントのメールアドレスは初期状態ではマスクされています。目のボタンで表示と非表示を切り替えられます。問い合わせ履歴はこのデバイスに保存されます。再起動後も記録は元の日時を保持し、再取得が必要なものとして示されます。過去に取得した値が、実行やリセットクレジットの使用を許可する根拠になることはありません。

Prism は API キー課金への切り替えやクレジットの購入を行いません。すべてのアカウントで、追加使用量、自動チャージ、利用枠の照会結果は情報としてのみ表示され、実行をブロックしません。利用可否はサービス側が判断し、支出上限は各サービスでユーザーが管理します。既存の Codex リセットクレジットを使用するには、選択したアカウントについて別途確認が必要です。 タスクの実行中もリセットクレジットを使用でき、タスクはそのまま続行されます。確認操作と重複リクエストの防止は引き続き適用されます。すでに終了したターンは自動で再開されません。 別のタスクの実行中でも、待機中のタスクのアカウント、モデル、推論レベルを選択できます。切り替えて続行すると既存のキューに入り、実行中のタスクを中断しません。 Claude の追加使用量は情報として表示され、Prism での実行をブロックしません。利用可否と課金は Claude のアカウントまたは組織の設定に従い、チームのクレジット消費や追加料金が発生する場合があります。

丸い送信矢印は実行中に停止ボタンへ切り替わります。追加指示の送信とキューへの追加は引き続き可能で、音声操作は追加しません。

アシスタントファイルとスキルは、アカウント間で共有できます。MCP の権限とアプリケーション接続は、実行環境ごとに設定する必要があります。アプリケーションの検出では、インストール済みのエントリーポイントを一覧表示します。検証操作では、対応する操作を別途確認します。

**共有機能**を開き、**共有機能を確認 → ローカルの最新を同期**を選ぶと、ローカルのスキルエントリーファイルとパスを前回の同期記録と比較できます。システムスキルと追加したフォルダーは、同期後に共有インデックスへ登録されます。**ソースと接続**で、参照したいプラグインごとに**スキル資料を接続**を選択します。次のタスクターンには参照先のインデックスが渡され、元のファイルは保存場所に残ります。

プラグイン一覧には、各ローカルキャッシュで認識できる最も新しいバージョンが表示されます。アンインストール済みのパッケージが含まれる場合があり、オンラインの最新版であることや、ツールが認証済みであることを示すものではありません。元のアプリでプラグインを更新してから、再度確認してください。Codex の MCP 接続は、各アカウントの独立した CLI で個別に設定・検証する必要があります。現在の Claude、Grok、Gemini の実行経路では外部 MCP が有効になっておらず、スキル資料を接続してもこの制限は変わりません。

### 開発

```powershell
npm test
npm run build
npm run build:desktop
```

単体テストでは、分離されたアカウントのテスト用データを使用します。任意のデスクトップ検証と実際の CLI を使った検証については、[scripts/README.md](scripts/README.md) を参照してください。実際の CLI を使った検証にはテストアカウントが必要で、サブスクリプションの利用枠を消費する場合があります。

問題を報告する際は、アプリと CLI のバージョン、再現手順、機密情報を伏せたエラーメッセージを含めてください。投稿前に、認証情報、アカウントの詳細、非公開の会話内容を削除してください。

### コントリビューター向けリリース規則

公開前に [AGENTS.md](AGENTS.md) と [RELEASING.md](RELEASING.md) を読んでください。ソフトウェアをリリースするたびに、新しいバージョン、変更不可のタグ一つ、英語と簡体字中国語の完全なリリースノートが必要です。`npm run release:check` と、変更に必要な検証を実行してください。ドキュメントのみの編集では、新しいソフトウェアリリースは不要です。
